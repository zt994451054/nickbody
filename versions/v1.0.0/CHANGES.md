## CHANGE-007 | 2026-07-29 | 需求变更 / 功能新增

**变更时当前阶段**：开发中
**变更内容**：跟练窗口右侧板块从绿色 2D 火柴人升级为由摄像头实时驱动的 3D 镜像角色（狐狸）。新增手绑骨资产 `mirror_fox.usdz`（16 骨），扩展 `UserJoints` 携带肘/腕与画面宽高比，新增纯逻辑 `MirrorPoseSolver` + `MirrorPoseSmoother` 完成 2D 关节 → 骨骼旋转的映射、抖动抑制与跟踪淡入淡出，新增 `MirrorSceneView` 渲染。资产缺失或骨骼不满足镜像要求时自动回落 2D 骨架。
**变更原因**：用户要求跟练右侧用固定 3D 模型实时呈现摄像头捕捉到的肢体动作。原 2D 火柴人只有头与双肩三个点，无法表达手臂，读不出动作幅度。

**已知边界**（写入文档而非默认用户已知）：
- 单摄像头只能给出 2D 关节位置，**手臂仅在正面平面镜像**，前后深度不做推测；头部因 Vision 提供真实人脸朝向而具备完整三轴。
- 无髋/膝/踝关节数据，**下肢不参与镜像**，保持静止站姿。

**影响范围**：

研发域：
- [x] 视觉资产 → 新增 `Sources/NickBodyCore/pet3d/mirror_fox.usdz`（手绑骨，Meshy 自动绑骨对 Q 版比例失败）
- [x] 关节数据 → `UserJoints` 增加肘/腕与 `aspectRatio`（Vision 双轴独立归一，缺此项手臂角度会算错）
- [x] 镜像求解 → 纯逻辑 `MirrorPoseSolver`：模型空间摆动求解 + 世界轴实测签号 + 角度上限
- [x] 抖动与兜底 → `MirrorPoseSmoother`：帧率无关一阶低通 + 逐肢跟踪强度淡入淡出
- [x] 渲染 → `MirrorSceneView`，与教练面板共用灯光；结果页与退出时同步暂停
- [x] 几何工具 → `shortestArc` 等从 `PlantedFootSolver` 提为共享 `RigMath`，避免复制既有修复
- [x] 调试入口 → `--mirror-probe` 脚本化方向核对窗口、`--workout` 直开跟练窗口

测试域：
- [x] 自动化测试 → 镜像求解签号/左右/宽高比/上限/兜底、平滑器帧率无关性、资产摘要一致性（全量 113 通过）
- [ ] 实机验收 → 真人站在摄像头前确认镜像跟随与延迟感（@winston，需人在机器前）

**首次实机反馈修复**（winston 2026-07-29）：
- 坐在桌前时镜像完全不动：头部动作被错误地挂在「身体识别」强度上，而人脸识别与
  身体姿态识别是两个**互相独立**的 Vision 请求，桌前场景常常只认得到脸。已拆成
  faceStrength（头/颈）与 bodyStrength（躯干）。
- 手腕拍不到时整条手臂被丢弃：改为肘可见即驱动上臂，仅前臂等待手腕。
- 头部动作在 240pt 面板里几乎看不出：45% 角度分配给颈部，让头真正产生位移。
- 两个角色的默认姿势都是绑骨用的 A 字姿（双臂平举），观感僵硬：改为自然垂手的
  站姿，镜像角色另加缓慢呼吸；宠物侧把该姿势折进静止变换，原有动作增量照常叠加。

**第二轮实机反馈修复**（winston 2026-07-30）：
- 狐狸左右方向与跟练宠物相反：它原本按镜子实现，但跟练小草的每个动作都按它
  **自己被点名的那一侧**执行（实测 `--pet-scene` 截图：「左侧倾」头顶倒向屏幕右、
  「右侧倾」倒向屏幕左、「左转头」脸转向屏幕右），做成镜子会导致六个动作全部与
  教练反向。改为跟随用户自己那一侧，两块面板方向自此一致。
- 自然站立时双手仍分别朝两侧翘起：姿态旋转此前把每根骨的模型旋转**绝对**写入，
  前臂的 11° 抵消了上臂的 42°，导致上臂下垂而两只手掌翻回 A 字姿方向。改为沿
  骨链累积（与 Blender pose bone、与宠物侧的局部 delta 合成一致）。
- 双肩与身体贴得过紧、看不出手臂：狐狸手臂根部本就位于躯干内部且无独立肩骨，
  垂到接近竖直就整条埋进身体。两个角色的下垂角度都收到远离竖直（狐狸 42°→26°、
  小草 34°→20°），并各加一点向前摆。取值由 Blender 渲染每个角色六套候选站姿的
  正面与 3/4 视图比对得出，不凭手感。
- 狐狸双腿外撇：资产本身是叉开建模的（大腿根 x=0.13、脚踝 x=0.27），且没有任何
  数据驱动腿部，所以一直保持该姿态。改为按各段偏离竖直的实测角度收回（大腿
  19.5°、小腿 7°），并给脚做等量反向旋转——脚会继承整条腿链的滚转，不补偿的话
  两只脚掌会内翻。脚的角度由前两个推导而非另行填写，避免日后走样。

**未修复（需产品决策）**：狐狸的嘴是**建模张开**的。去掉贴图渲染素模仍可见上唇
凸起、下唇环与真实凹陷，且 16 骨骨架没有下颌骨，任何姿态都关不上。删洞补面、
重度平滑、腔内改涂唇色三条脚本路线均已尝试并失败（记录在
`plans/003-live-camera-mirror.md`，避免重复踩）。要做成闭嘴微笑，需用闭嘴设计
重新生成模型并重跑手绑骨流程——骨骼表是按当前网格量出来的，须重新测量、重新
验证绑骨、并重新确认造型，属于范围决策而非缺陷修复。

**处理状态**：⏳ 处理中
